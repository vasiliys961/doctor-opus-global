# Original NIH CXR CPU worker — measured contest integration (2026-11-01)

## What genuinely ran
- The original TorchXRayVision `densenet121-res224-nih` pretrained DenseNet121, using the official NIH checkpoint, not a mock. GitHub Actions run [41336018997](https://github.com/vasiliys961/doctor-opus-global/actions/runs/41336018997) validates its SHA256 `31a5475c6b1383a7edbfcaf96af9ce302eb9969cfe28b6b8b5859afc6f274fdf`, source image checksum and 6 legitimate trained outputs. One public source PNG from the upstream TorchXRayVision tests, not private patient data. Actual warm-CPU inference was 229 ms. These image-level model scores are **not calibrated disease probabilities** and are not reader-adjudicated.
- A separate real warm original-model CPU HTTP service handled **10 simultaneous requests** (same public image, deliberately repeated only to measure throughput) at [41336261550](https://github.com/vasiliys961/doctor-opus-global/actions/runs/41336261550): success **10/10**, p50 **1.376 s**, p95 **2.773 s**, total batch wall **2.774 s**, no GPU, no LLM calls. These are NOT ten independent clinical examples or a full MAST workload. Original worker and all weights are kept exclusively on the ephemeral GitHub Actions CPU runner.
- The contest clinical-chat endpoint now invokes the optional external original CPU worker through `xrv-cpu-worker-client.ts` when a trusted HTTPS worker and source-transfer authorization are configured, while always starting independent Gemini/Opus imaging concurrently. It imposes an 8-second detector deadline and no more than 1.5 seconds additional wait after vision. A missing, failed or late detector is **not** negative imaging evidence. The mother clinical consilium continues on source vision regardless. Parent `main` remains untouched.
- New `totalSpecialistCostUsd`, `totalConsiliumCostUsd`, `totalEstimatedCostUsd`, `elapsedMs` and `cpuDetectorRuns` record downstream diagnostics consumption. These are provider-reported estimates, not externally reconciled billing.

## How to operate (operator-controlled, never automatic provisioning)
1. On a dedicated Linux CPU host, install CPU PyTorch, compatible torchvision, TorchXRayVision (the GitHub Actions proof pinned `torchxrayvision==1.5.7`), Pillow and dependencies.
2. Manually provision `nih-densenet121-d121-tw-lr001-rot45-tr15-sc15-seed0-best.pt`, verify SHA256 shown above. The worker checks SHA before importing/loading model and does not download weights.
3. Launch `python benchmark/scripts/xrv_nih_cpu_worker.py --weights /model/nih-densenet121-d121-tw-lr001-rot45-tr15-sc15-seed0-best.pt --serve --host 127.0.0.1 --port 8765` with a high-entropy `XRV_WORKER_TOKEN`. Place behind a trusted HTTPS reverse proxy exposing only `/infer` (optionally `/healthz`) with authentication; never publish the local HTTP service directly.
4. In the contest-only Vercel server environment, set `MAST_XRV_CPU_URL=https://your-trusted-worker/infer`, `MAST_XRV_CPU_TOKEN`, `MAST_XRV_CPU_WEIGHT_SHA256` and **only when the study rights permit the separate-host image transfer** `MAST_XRV_CPU_INPUT_RIGHTS_GRANTED=true`. No client-supplied worker URL, GPU provisioning or model downloads on Vercel.
5. By default, all optional worker variables are absent, so full source Gemini/Opus plus mother consilium continues with the detector `disabled`. A configured worker is not proof of an available worker; only a completed original model inference with matched source/model checksums becomes unverified machine evidence.

## Known limitations / next trials
- No permanent external Linux CPU host is provisioned by this experiment; a GitHub Actions runner is ephemeral and not an always-on MAST API.
- The first pilot only accepts a single PNG radiograph in `chest-xray`. JPEG, multiple views and CT/MRI original models remain out of scope of this CPU worker. The independent vision pipeline can read the supported MIME types even without XRV.
- The 10-request test covers the original CPU worker **only**. End-to-end Gemini/Opus 5-role consilium at 5–10 concurrent MAST calls under 300 seconds remains unmeasured and must be tested with strict spend caps.
- Needs original physician-verified chest-Xray positive/negative cases and comparison to native expert labels. No clinical sensitivity, specificity, official MAST leaderboard or independent patient validation can be inferred from this infrastructure test.
